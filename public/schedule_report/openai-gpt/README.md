# デイリーブリーフの入口と独立更新

配置先: s-omy/pages、main、schedule_report/openai-gpt/。
index.html と hub.js は共通の入口。各カテゴリの latest.json を閲覧時に個別取得します。
ゲームとVTuberの公開日が異なる場合も、それぞれの発行日を表示します。
メタデータが読めない場合は一般的な紹介文とリンクを残し、日付取得失敗を表示します。
ブラウザは取得時にキャッシュを使わないよう要求しますが、CDNや配信の反映には時間差があり得ます。

## 各レポート更新処理の担当範囲

games担当は games/ 内だけ、vtuber担当は vtuber/ 内だけを変更します。
各担当はレポートHTML、日付別アーカイブ、カテゴリ内一覧、元レポート、latest.jsonを同じコミットで更新してください。
共通 index.html と hub.js は日々の更新では変更しません。
latest.json は schemaVersion=1、date=YYYY-MM-DD（JSTの発行日）、tagline=1〜120文字のプレーンテキストです。
キャッチコピーはその号の内容に基づいて作成し、本文で未検証の事実を検証済みとして断定しないでください。

## 同時コミットの競合を避ける手順

ファイルの分離で内容の競合を避けます。ただし、同じmainへの同時pushは先端更新の競争が残るため、次の手順が必要です。

1. コミット直前にmainの最新コミットとtreeを読みます。
2. そのtreeをベースに、自分の担当ディレクトリ内の変更だけを重ねてコミットを作ります。古いリポジトリ全体のスナップショットで置換しないでください。
3. 先端SHAの一致を条件に、force=falseでmainを更新します。
4. 別担当が先に更新して拒否された場合は、mainを再取得し、その新しいtree上で自分の変更だけを再適用して新しいコミットを作り直します。force pushはしません。
5. 同じカテゴリに自分より新しい発行日が既にある場合は、古い号で最新号・latest.jsonを巻き戻さず、日付別アーカイブの追加だけにします。同一日付の既存号に変更がある場合は差分を確認してから扱います。
6. 数回の再試行でも更新できなければ終了し、次回の実行または人による確認に委ねます。別カテゴリの変更は削除しません。

Git CLIを使う場合も最新状態を取り込み、自分の変更だけをrebaseして通常pushします。競合時は上書きせず差分を確認します。
根拠: https://docs.github.com/en/rest/git/refs#update-a-reference

## 現在の適用範囲

入口と独立メタデータは実装済みです。既存ChatGPT Scheduledの設定と、HTML化・GitHub投稿の自動処理は今回変更していません。
今後スケジューラから自動コミットする処理を設ける際は、上記担当範囲・再試行手順とlatest.jsonの更新をその処理に組み込んでください。
この構成だけで既存チャットが自動的にGitHubへ投稿するようになるわけではありません。
