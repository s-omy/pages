# 1. Executive Summary

今週を象徴するニュースは、Metaの**Muse日本上陸**です。

Metaは10月23日、パーソナルAIエージェント「Muse」を日本で提供開始しました。北米以外では日本が最初の提供地域です。Museは質問に回答するChatbotではなく、Gmail、Google Calendar、Instagramなどと接続し、Webブラウザ操作、フォーム入力、旅行予約などをユーザーの代わりに進める**Personal AI Agent**として設計されています。日本ではメルカリ、マネーフォワード ME、チケットぴあとの連携も進めるとしています。 [Facebook](https://about.fb.com/ja/news/2026/10/muse-personal-ai-agent-launches-in-japan/?utm_source=chatgpt.com)

これは単に「Meta版ChatGPTが出た」というニュースではありません。

2026年の個人向け生成AIが、

**Chatbot → Search/Research → AI Browser → Personal Agent**

へ進んでいることを強く象徴しています。

特に現在の主要プレイヤーを見ると、

- ChatGPT：会話を起点にWork・Apps・Agentへ拡張
- Gemini：Google Workspaceと一体化する汎用Agent
- Perplexity：検索を起点にComet / Computerへ拡張
- Meta：Museを最初からPersonal Agentとして設計

という**異なる入口から同じ「Personal AI」へ収束する動き**が見えてきます。GoogleもGeminiをGmail、Drive、Docs、Sheets、Calendar等を横断する「universal agent for work」として展開しています。 [Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026?trk=public_post_comment-text\&utm_source=chatgpt.com)

Metaはモデル側でも攻勢を強めています。10月12日に公開した**Muse Wonder / Muse Wonder Full**はPersonal/Professional Agent向けの同社最上位モデルで、Active MemoryとActive Focusを備えています。さらに10月19日には、30Bパラメータのオープンソース・オンデバイスAgentモデル**Muse Glimmer 30B**を公開しました。約4bit量子化でconsumer hardware上のローカル実行を狙ったモデルです。 [Facebook](https://about.fb.com/news/2026/10/introducing-muse-wonder-models/?utm_source=chatgpt.com)

このためMetaについては、今後この週報でも「SNS企業のAI」ではなく、

> **Frontier Model + Personal Agent + Device + Social Graph**

を統合する主要AIプレイヤーとして追う必要があります。

もう一つ、個人的な利用に直結するのが**Perplexity / Comet**です。

PerplexityはComet Assistantを刷新し、複数タブ・複数サイトにまたがる長時間タスクへの対応を強化しました。社内評価では旧Assistant比23%改善としています。またブラウザを実際に操作する場合には事前承認を求める方式へ変更しています。 [Perplexity AI](https://www.perplexity.ai/ja/hub/blog/the-new-comet-assistant?utm_source=chatgpt.com)

さらにPerplexityは10月20日、ComputerをMac上で完全ローカル実行できるようにしました。検索サービスだったPerplexityが、

**Search → Browser → Computer → Local Agent**

へかなり速い速度で拡張していることが分かります。 [Perplexity AI](https://www.perplexity.ai/en-GB/hub/blog?utm_source=chatgpt.com)

したがって、今週の最も重要な認識更新は、

> **「どのLLMが一番賢いか」だけでなく、「どのAIが自分のWeb・アプリ・ファイル・予定・行動へ最も自然に接続されるか」が、個人利用では重要な競争軸になった**

という点です。

# 3. フロンティアモデルと周辺技術

## 3.1 今週の主役：Meta Muse family

### Muse Wonder / Wonder Full

MetaはMuse Wonderシリーズを「personal and professional agentic tasks」向けの最上位モデルとして位置付けています。

重要なのはベンチマーク数値以上に、

**Active Memory**  
→ 会話をまたいで関連情報を保持・想起する

**Active Focus**  
→ 一度失敗しても別アプローチを試し、タスクを継続する

という設計思想です。 [Facebook](https://about.fb.com/ja/news/2026/10/introducing-muse-wonder-models/?utm_source=chatgpt.com)

従来のLLMの評価軸だった、

- Reasoning
- Coding
- Long Context

に加えて、

- Persistence
- Recovery
- Memory
- Tool use

がFrontier Model評価の中心へ入っています。

これはGPT、Claude、Geminiにも共通する流れです。

---

## 3.2 Muse Glimmer 30Bは別方向で重要

10月19日にMetaが公開したMuse Glimmer 30Bは、今回の週報ではかなり注目したい技術です。

30Bという比較的小規模なモデルで、

- Text + Image入力
- Multi-step reasoning
- Tool use
- Failure recovery
- 100以上の言語
- 約4bit量子化
- Consumer GPUでのローカル実行

を狙っています。Apache 2.0で公開されています。 [AI Meta](https://ai.meta.com/research/publications/muse-glimmer-30b-an-on-device-agentic-model?utm_source=chatgpt.com)

### なぜ重要か

Frontier AIには現在、二つの方向があります。

**巨大Cloud Model**

GPT / Claude / Gemini / Muse Wonder

と、

**十分に賢いLocal Agent Model**

Muse Glimmer / Gemma / Qwen等です。

Personal AIではすべてをCloudへ送る必要はありません。

今後、

> Local modelで日常処理  
> → 難題だけFrontier Cloud Model

というHybrid AIがかなり現実的になる可能性があります。

PerplexityもComputerのLocal実行を強化しており、これは偶然ではありません。 [Perplexity AI](https://www.perplexity.ai/en-GB/hub/blog?utm_source=chatgpt.com)

## 今週のテーマ：「Specを書くこと」が目的ではない

Specification-Driven Developmentの本質は、

> AIに大量の仕様書を読ませる

ことではありません。

Microsoftの解説はかなり分かりやすく、

**Stakeholder intent → Requirements → Design → Implementation → Validation**

の途中で生じる「意味の損失」を減らす方法としてSDDを説明しています。 [Microsoft Developer](https://developer.microsoft.com/blog/spec-driven-development-ai-native-engineering/?utm_source=chatgpt.com)

この理解から始めることを推奨します。

### ② 実践：Kiro — Specs just got faster (and smarter)

KiroのSpec modeが、

**Requirements → Design → Tasks → Implementation**

をどう扱っているかを見る教材です。

重要なのは「全部を重厚なSpecにしない」という点で、簡単な変更と複雑な変更で流程を変える思想も参考になります。 [Kiro](https://kiro.dev/blog/faster-smarter-specs/?utm_source=chatgpt.com)

[Kiro Spec解説](https://kiro.dev/blog/faster-smarter-specs/?utm_source=chatgpt.com)

---

### ③ 実証研究：Google — Spec-Driven Test Generation

ここから一段深くします。

GoogleのProduction Bugを対象とした研究では、AgentにいきなりTestを書かせるより、

**Pre-condition / Post-condition / Undefined Behavior**

を一度Specificationとして書かせてからTest生成させることで、bug detection rateが9.8ポイント改善したと報告しています。 [Google Research](https://research.google/pubs/grounding-ai-agents-in-contracts-an-empirical-evaluation-of-spec-driven-test-generation/?utm_source=chatgpt.com)

これは「Specがなぜ効く可能性があるのか」を比較的具体的に確認できる研究です。

---

### ④ 批判的視点：Spec-Driven Development as Prescribed and as Practiced

10月15日に改訂された研究では、21人へのインタビューと266 repositoryを分析しています。

結果は単純な「SDD最高」ではありません。

利用者は、

- Agentの挙動が安定した
- intentを明文化できた

というメリットを感じる一方、

- Planning cost
- Review cost
- Spec decay

も報告しています。 [alphaXiv](https://www.alphaxiv.org/abs/2608.25202?utm_source=chatgpt.com)

これは非常に重要です。

**SDDにもコストがあります。**

したがって、

> 何でもSpec化

ではなく、

> **複雑・長期・複数制約がある作業ほどSpecを厚くする**

のが現実的です。

各社が同じ方向へ進んでいます。

つまり、

**AI SafetyはPrompt Engineeringだけでは成立しない**

ということだけ今週は押さえておけば十分です。

# 11. 法制度・政策

## 日本：AI・デジタル改革推進会議が始動

日本では10月22日、政府の**AI・デジタル改革推進会議**が初開催されました。

政府は年末までに、

- 2030年のAX像
- AI・デジタル改革原則
- AX社会実装アクション

を「中間整理」としてまとめる予定です。

またAI法を含む制度の見直しや、AISIの機能強化も議論対象になります。 [デジタル庁](https://www.digital.go.jp/councils/ai_digital?utm_source=chatgpt.com)

### 注目点

日本の政策は現在、

**AIをどう規制するか**

だけでなく、

**AIをどう社会実装するか**

にかなり比重があります。

これは今後、

行政・企業のAI Agent利用を後押しする可能性があります。

## EU：AI Actは実際のEnforcementへ

# 今週の結論

これまでのレポートは、AIを「企業システムへ安全に導入するエンジニア」の視点に寄りすぎていました。

今週のMuseは、その視点だけでは拾い切れない重要な変化です。

現在生成AIで最も大きな動きの一つは、

> **AIが「使うサービス」から「日常生活とWebの間に常駐するインターフェース」へ変わりつつあること**

です。

Meta Muse、Perplexity Comet/Computer、Gemini、ChatGPTは、そのアプローチこそ違いますが、いずれもこの方向へ進んでいます。

一方で開発分野では、仕様駆動開発も「難しいAgent Governance技術」として捉える必要はありません。

まずは、

> **人間の意図をAIへ渡すときに失われる情報を減らし、生成結果が本当に意図通りか確認しやすくする手法**

として理解すれば十分です。

そこからKiro、Spec Kit、cc-sdd、AGENTS.md、Skills、MCP、Evaluation、Governanceへ段階的に進めばよい。

この二つを合わせると、今後追うべき生成AIは、

**「モデルがどこまで賢くなったか」  
「一般ユーザーが何を任せられるようになったか」  
「開発者はAIとどう協働すべきか」  
「社会や企業はそれをどう受け入れようとしているか」**

の4軸です。

今後の週報は、この4軸を中心にした方が、現在のAI全体の変化を把握するという目的に合っています。
