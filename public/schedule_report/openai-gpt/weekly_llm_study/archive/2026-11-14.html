5. Agentic Developmentとモデル選択

Copilotでは11月9日にFable 5.2、10日にCarbonのGAを告知。対象プランへの展開は段階的です。Fable 5.2はBusiness / Enterpriseで管理ポリシーが既定オフ、通常は安全性分類のためのデータ保持が必要で、対象企業に対する例外条件も説明されています。Carbonと同じ条件だと考えないことが大切です。

GitHub — Fable 5.2 in Copilot（11/9） ／ GitHub — Carbon in Copilot（11/10）

ここからの実践提案は、モデルだけを変更し、Repository、仕様、Agent指示、テストを固定することです。ContextはAIに渡す情報、HarnessはToolsや実行手順・評価を含む周辺の仕組み、と考えると整理しやすくなります。

  • 機能テストが通ったかだけでなく、認可・監査のルールを守ったかを記録する。
  • 不明点を質問したか、不足情報を捏造したかを確認する。
  • 完了までの時間と人による修正時間を測る。
  • 高いモデルへ切り替える前に、失敗原因が仕様不足かを確認する。

6. 仕様駆動開発：モデルが変わっても品質基準を残す

今週の学習テーマは、Requirements → Design → Tasks → Implementation → Test / Evidenceのつながりです。最初から大きな仕様書を作る必要はありません。小さなAPIの振る舞いを明文化し、実装がその条件を満たすか確認できれば、最初の一歩として十分です。

成果物Java業務APIでの例確認すること
Requirements本人だけが明細を参照できる誰に何を許可するかが明確か
Design認可チェック、例外、監査の配置業務共通Frameworkの規約に沿うか
Tasks実装・テスト・文書更新の小タスクテストが最後に抜け落ちていないか
ImplementationAPIと認可処理仕様外の変更が混ざっていないか
Test / Evidence成功・未認証・他人の明細の試験要求と結果を対応付けられるか

Kiroの10月30日記事は背景資料として再確認。Specification Hardeningは要求文の兆候からCWEに基づくセキュリティ要件を提案しますが、コードの安全性を証明したり、SAST・DAST・人間のレビューを代替したりするものではありません。

8. ガバナンス・セキュリティ・品質

GitHubは11月9日にActions Workflowログ内のSecret検出をPublic Previewとして発表。対象はGitHub Enterprise Cloudと所定のSecret Protection / Advanced Security契約等で、既定オフです。有効化後に完了する実行が対象で、過去ログの一括再検出は行いません。Preview中はアラート通知も送られないため、一覧を直接確認する必要があります。

GitHub — Cloudflare Service Token検出（11/12）

AI Browserにも、実際に止める境界を用意する

11月12日のChrome Enterprise記事は、医療向け端末連携とともに、コピー・貼り付け・フォーム送信・印刷・画面取得などのDLP制御を紹介しています。既存の保護機能と新しい連携をまとめた記事であり、DLP全体がこの日に初めて登場したとは扱いません。
