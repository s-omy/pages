1. Executive Summary

GPT-6 Cyberは、セキュリティ専門タスクに特化したモデル。OpenAI公表のExploitGymでは48.5%を記録し、GPT-5.6 Cyberの32.1%から改善しました。LinuxやFirefoxの脆弱性調査でも実績を報告しています。

出典表記：OpenAI+1（添付に記事URL未収録）

今週の結論は、AIの進化が「より良い回答」から、専門業務を実行する能力、複数工程を継続する能力、誰でもソフトウェアやコンテンツを作れる能力へ広がっていることです。

5. 仕様駆動開発・Context / Harness設計

今週の学習テーマ：仕様だけでなくAgentの作業ルールもVersion管理する

GitHub DependabotのAgent Package Manager対応は、SDDの学習にも関係する重要な更新です。

これまでのソフトウェア開発では、Mavenやnpmの依存ライブラリをVersion管理していました。今後はAgentが参照するSkills、Instructions、Promptsも同様に変更管理する必要が生じます。

仕様駆動開発で管理する4つの資産

Specification

何を実装するか

Context / Skills

何を知り、どう作業するか

Policy

何を許可・禁止するか

Evidence

何をもって完成と判断するか

7. AIガバナンス・セキュリティ・品質・監査・コスト

今週の重要な示唆は、GPT-6 Cyberの発表から得られます。

高度なAIには、脆弱性を発見する能力と同時に、許可された範囲を守る能力が必要です。OpenAIは、GPT-6 Cyberの評価でScope外の操作を避ける能力も測定しています。

出典表記：OpenAI（添付に記事URL未収録）

一般のCoding Agentでも、以下の区別が必要です。

  • 生成・提案する権限： コード、設定、テスト、IaCの変更案を作る
  • 実行・適用する権限： Repositoryへ反映、CI/CD実行、本番環境変更を行う

後者には人間の承認、独立したPolicy Check、Audit Logを組み合わせます。

またGitHubのCopilot Usage Metrics APIは、Code Review指摘への対応状況も集計できるようになりました。AIの利用量だけでなく、レビューが実際に改善へつながったかを測る方向です。

出典表記：GitHub Changelog（添付に記事URL未収録）
